# fleet: its files carry a version, and it only calls `sessions`

`fleet` is turned on per project, and several sessions of a project run it at once, sharing the files under the project's `<project>/.claude/fleet/` (the list is at the top of `hooks/decisions.ts`). After an update the owner restarts every session, so there is no code for older versions: version skew must be harmless and visible, as in `sessions` (`.claude/rules/sessions-wire-format.md`).

- **Wire files carry `format`** (`FORMAT` in `hooks/decisions.ts`): `<project>/.claude/fleet/decisions/queue/`, `<project>/.claude/fleet/decisions/answers/`, `<project>/.claude/fleet/decisions/applied/`, `<project>/.claude/fleet/decisions/last`, `<project>/.claude/fleet/decisions/prune/`, `<project>/.claude/fleet/events/` (the landings, `latest`, `claims/`), `<project>/.claude/fleet/reads/`, `<project>/.claude/fleet/state/` (a record's versions in `revs/`, `suspects.json`, `checks/`, `checks-stamp.json`, `sweeper.json`, `commit.json`, `stamps.json`, `lifts.json`, `down.json`, `wakes.json`; `hooks/records.ts`, `hooks/roster.ts`) and an instance's `<project>/.claude/fleet/instances/<slug>/` (`state.json`, `spend.json`, `nudges.json`, `seed-<ref>.json`). Change a key or its meaning → raise `FORMAT` in the same commit; a new key a reader can ignore isn't a change. A reader that meets another format acts on nothing and says to restart (`u`): `/fleet` lists such decisions apart and refuses to answer them, an asker doesn't deliver an answer it can't read, and an event or reads file of another format is counted in `/fleet status` and not used. A decision of a kind a reader doesn't know (a `change` carries no questions, so an older `fleet` can't answer it) is listed apart and never answered.
- **Person data has its own version**: the register (`registerFormat`, `REGISTER_FORMAT`), `config.json` (`configFormat`, `CONFIG_FORMAT`), `world.json` (`worldFormat`, `WORLD_FORMAT` in `hooks/changes.ts`; a newer one turns the world off in that session, it never holds a write it can't read), `roster.json` (`rosterFormat`, `ROSTER_FORMAT` in `hooks/roster.ts`; `/fleet up` refuses a newer one) and `outbound.json` (`outboundFormat`, `OUTBOUND_FORMAT` in `hooks/outbound.ts`; a newer or broken one allows nothing but this machine: the hard line never opens by itself). They only gain fields, a write keeps the fields it doesn't know, and a newer version is left untouched and said (restart, `u`), never silently ignored. A template's `template.json` has `templateFormat`; `/fleet init` refuses a newer one. An instance's settings file (`<project>/.claude/fleet/instances/<slug>.json`) is generated by every `/fleet up`, so it carries no version (Claude would read a key of `fleet`'s as a setting).
- **The project folder is fleet's data folder.** `fleet` keeps no `$.store` and writes only in the project: its `<project>/.claude/fleet/`; on `/fleet init` the template's role files in `<project>/.claude/agents/` and its folders, never over a file that's there; and the command-level record an applied change names. It reads outside it only what Claude gives it (`CLAUDE_JOB_DIR`'s `state.json`, its own `plugin.json` and `templates/`) and the folder `FLEET_TEMPLATES_DIR` names; a new place it reads or writes outside the project gets an environment override, so test sessions never touch the owner's files.
- **Single writer or no-clobber.** A queue file is written once, by the session that asked, and so are a change's draft and diff and an outbound's call; answers, drops, a change's claim when it's applied (an outbound's when it's sent), register records, prune markers, events (each under a name of its own), outside-change claims, a record's versions (on a name taken, the next number) and an instance's seed marker are published with `ln` from a file in `<project>/.claude/fleet/decisions/tmp/` (the first one wins); notes, `last`, a session's own reads file, an instance's heartbeat, spend and nudges (only its own `fleet` writes them), the sweeper's `suspects.json`, `commit.json` and `wakes.json`, a file's check results (whoever ran the check last wins), and the person's `stamps.json`, `lifts.json` and `down.json` (the last write wins) replace with `mv`; `<project>/.claude/fleet/events/latest` is only a trigger, rewritten in place. The sweeper's lease (`<project>/.claude/fleet/state/sweeper.json`) is replaced with `mv` by whoever holds it or takes it once it's 90 s old, and a taker sweeps only when it still finds itself there 2 s later: a minute of two sweepers is harmless, since what they write is idempotent. No locks.
- **Every command through `run`**, from `/` (it exists; every path is absolute), with a timeout; only a project's check script and an outbound command the person approved run from a project folder (the project's, or the one the outbound was drafted in, when it still exists). `$.process.run` appears nowhere else.
- **Calls only to `sessions`** (`plugins/sessions/docs/plugin-contract.md`): never hook a `sessions.*` event, never read its state, store or `sessions-data/` files; find what's served with `has()` (raced against 500 ms; `start`, `wake` and `setMarks` came after api 1's first release, so they're called as `$.sessions.start!(…)` once `has()` said yes) and race every call; no `$.sessions` call in `session.start` (it runs before `sessions` starts). `dev/fleet/ci.sh` checks the first and the second.
- **Delivery state lives in `$.state`** (it survives a hot reload; module variables don't, and one double submit came from that): the decisions in flight, the seed sent and a nudge in flight, each thread's reads and the gate's "told once", the conversation's outside mark, whose turn is running (the person's, and the start of his words), when the conversation started and when it last landed. What must outlive a restart is in the files (the outside mark in the reads file; an instance's last landing and conversation start in its heartbeat).
- **Light: two things block.** (1) The settings `/fleet up` writes for an instance deny its own tools (`Edit(//<path>)`, which covers Write) on the command-level files only (the charter, `roster.json`, `world.json`, `outbound.json`, the role files, the check scripts, `world.json`'s `"command"` records) and on `<project>/.claude/fleet/instances/`; `fleet`'s gate refuses the same writes with how to file a `change`. A `change` is written by `fleet` only when the person applies it, once, while the file is at the version it was drafted on and the draft is the one filed or the one he confirmed; or as it's filed, when the person typed the turn that filed it (origin `composer`, never a launch prompt, matched to the turn by its text) in a conversation with no outside mark. (2) The one hard line, in background sessions only: a Bash command or MCP call that would send the project's content to a third party (`hooks/outbound.ts`) is refused with how to draft it (`mcp__fleet__send`); `fleet` runs a draft only when the person answers `send`, once (claimed no-clobber), exactly as shown, while the call and every file it sends are at the version he saw. A gate that throws before the call ran refuses one that may reach the network. No sandbox, no git denies, no other permission rule; a roster's own `permissions` are its, and `bypassPermissions` is never started.
- **Outside content marks, never holds.** WebFetch, WebSearch, an outside service's read and a command's web read mark the conversation until `/clear`; the mark only keeps a change from being applied as filed and labels what the session files. It never travels through files: a reader of a marked session's file isn't marked (an event's `outside` is provenance for the brief).
- **The shared files are coordination, not security.** The gate refuses a stale write, or a write citing a pin its thread hasn't read as it is, once (no second try under `strict`), and fails open (`.catch` → `next(e)`); Bash is never held, only recorded after the fact (landed blind); suspects and failed checks are flags that hold nothing; a digest carries path, who, when, versions and a check's message, never a file's content (of a change line only its kind). A check script runs only while the person's stamp (`/fleet accept checks`) matches the checks and their scripts, since `fleet` runs it as the person with no prompt. The world commit adds and commits only world paths, with `--only`, never in a linked worktree, and never pushes.
- **Budgets and cadence mark, never hold.** At 80% an instance is told; at 100% its row is marked, it's neither woken nor nudged, and a new helper (`agent.spawn`) is refused with why; its turn and every other tool go on. An instance that lands nothing in its cadence period is marked (◷) and nudged once (or woken once). Wakes are coalesced: an instance's own nudges (a digest, a cadence, a fresh period) and the sweeper's wakes share `wakes.everyMin` and `wakes.perDay`. A fresh period (`/clear` from the instance's own timer, then its journal as `fleet`'s prompt) runs only when it's idle, nothing of `fleet`'s is on its way, and its journal was written since the conversation started.
- **No platform code.** `fleet` runs the same on macOS and Linux: `$.fs`, `$.clock`, `ln`, `mv`, `rm`, `mkdir`.
