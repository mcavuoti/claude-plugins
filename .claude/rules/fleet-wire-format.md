# fleet: its files carry a version, and it only calls `sessions`

`fleet` is turned on per project, and several sessions of a project run it at once, sharing the files under the project's `<project>/.claude/fleet/` (the list is at the top of `hooks/decisions.ts`). After an update the owner restarts every session, so there is no code for older versions: version skew must be harmless and visible, as in `sessions` (`.claude/rules/sessions-wire-format.md`).

- **Wire files carry `format`** (`FORMAT` in `hooks/decisions.ts`): `<project>/.claude/fleet/decisions/queue/`, `<project>/.claude/fleet/decisions/answers/`, `<project>/.claude/fleet/decisions/last`, `<project>/.claude/fleet/decisions/prune/`, `<project>/.claude/fleet/events/` (the landings, `latest`, `claims/`), `<project>/.claude/fleet/reads/` and `<project>/.claude/fleet/state/` (a record's versions in `revs/`, `suspects.json`, `checks/`, `checks-stamp.json`, `sweeper.json`, `commit.json`; `hooks/records.ts`). Change a key or its meaning → raise `FORMAT` in the same commit; a new key a reader can ignore isn't a change. A reader that meets another format acts on nothing and says to restart (`u`): `/fleet` lists such decisions apart and refuses to answer them, an asker doesn't deliver an answer it can't read, and an event or reads file of another format is counted in `/fleet status` and not used.
- **Person data has its own version**: the register (`registerFormat`, `REGISTER_FORMAT`), `config.json` (`configFormat`, `CONFIG_FORMAT`) and `world.json` (`worldFormat`, `WORLD_FORMAT` in `hooks/changes.ts`; a newer one turns the world off in that session, it never holds a write it can't read). They only gain fields, a write keeps the fields it doesn't know, and a newer version is left untouched and said (restart, `u`), never silently ignored.
- **The project folder is fleet's data folder.** `fleet` keeps no `$.store` and writes nothing outside `<project>/.claude/fleet/`. It reads outside it only what Claude gives it (`CLAUDE_JOB_DIR`'s `state.json`, its own `plugin.json`); a new place it reads or writes outside the project gets an environment override, so test sessions never touch the owner's files.
- **Single writer or no-clobber.** A queue file is written once, by the session that asked; answers, drops, register records, prune markers, events (each under a name of its own), outside-change claims and a record's versions (on a name taken, the next number) are published with `ln` from a file in `<project>/.claude/fleet/decisions/tmp/` (the first one wins); notes, `last`, a session's own reads file, the sweeper's `suspects.json` and `commit.json`, and a file's check results (whoever ran the check last wins) replace with `mv`; `<project>/.claude/fleet/events/latest` is only a trigger, rewritten in place. The sweeper's lease (`<project>/.claude/fleet/state/sweeper.json`) is replaced with `mv` by whoever holds it or takes it once it's 90 s old, and a taker sweeps only when it still finds itself there 2 s later: a minute of two sweepers is harmless, since what they write is idempotent. No locks.
- **Every command through `run`**, from `/` (it exists; every path is absolute), with a timeout; only a project's check script runs from the project's folder (it exists: `fleet` found its `<project>/.claude/fleet/` there). `$.process.run` appears nowhere else.
- **Calls only to `sessions`** (`plugins/sessions/docs/plugin-contract.md`): never hook a `sessions.*` event, never read its state, store or `sessions-data/` files; find what's served with `has()` (raced against 500 ms) and race every call; no `$.sessions` call in `session.start` (it runs before `sessions` starts). `dev/fleet/ci.sh` checks the first and the second.
- **Delivery state lives in `$.state`** (it survives a hot reload; module variables don't, and one double submit came from that): the decisions in flight, and each thread's reads and the gate's "told once". What must outlive a restart is in the files.
- **The shared files are coordination, not security.** The gate refuses a stale write, or a write citing a pin its thread hasn't read as it is, once (no second try under `strict`), and fails open (`.catch` → `next(e)`); Bash is never held, only recorded after the fact (landed blind); suspects and failed checks are flags that hold nothing; a digest carries path, who, when, versions and a check's message, never a file's content (of a change line only its kind). A check script runs only while the person's stamp (`/fleet accept checks`) matches the checks and their scripts, since `fleet` runs it as the person with no prompt. The world commit adds and commits only world paths, with `--only`, never in a linked worktree, and never pushes; `fleet` adds no git denies or permission rules.
- **No platform code.** `fleet` runs the same on macOS and Linux: `$.fs`, `$.clock`, `ln`, `mv`, `rm`, `mkdir`.
