# fleet: its files carry a version, and it only calls `sessions`

`fleet` is turned on per project, and several sessions of a project run it at once, sharing the files under the project's `<project>/.claude/fleet/` (the list is at the top of `hooks/decisions.ts`). After an update the owner restarts every session, so there is no code for older versions: version skew must be harmless and visible, as in `sessions` (`.claude/rules/sessions-wire-format.md`).

- **Wire files carry `format`** (`FORMAT` in `hooks/decisions.ts`): `<project>/.claude/fleet/decisions/queue/`, `<project>/.claude/fleet/decisions/answers/`, `<project>/.claude/fleet/decisions/applied/`, `<project>/.claude/fleet/decisions/last`, `<project>/.claude/fleet/decisions/prune/`, `<project>/.claude/fleet/decisions/judge/` (a choice's proposal, `hooks/judges.ts`), `<project>/.claude/fleet/decisions/overrules/` (an overrule on its way to its asker and the reviewer), `<project>/.claude/fleet/events/` (the landings, `latest`, `claims/`), `<project>/.claude/fleet/reads/`, `<project>/.claude/fleet/state/` (a record's versions in `revs/`, a version's author corrected in `revs/<id>/<n>.by.json`, the confirmations of files checked against a record in `confirms/`, `suspects.json`, `checks/`, `checks-stamp.json`, `sweeper.json`, `commit.json`, `stamps.json`, `lifts.json`, `down.json`, `wakes.json`, `intake.json`, `alerts.json`, an alert's claim in `alerts/<day>/`, `channel-stamp.json`, a slot's leases and line in `slots/`, a session's judge calls in `judges/<day>/`, the live areas in `judges.json`, the code watch's markers and overlaps in `code.json`, the open items nobody owns, their offers, the capacity line and the quiet runs in `work.json`, the pins it asked sessions for in `pinned.json`, the reproduction items it opened in `reproduce.json`, a Write or Edit of a shared file in flight in `writing/`; `hooks/records.ts`, `hooks/roster.ts`, `hooks/intake.ts`, `hooks/channel.ts`, `hooks/slots.ts`, `hooks/code.ts`), intake's dedup marks (`<project>/.claude/fleet/intake/seen/`), the run register (`<project>/.claude/fleet/runs/`: `run-<n>.json`, `run-<n>.done.json`, `run-<n>.recorded.json`; `hooks/runs.ts`) and an instance's `<project>/.claude/fleet/instances/<slug>/` (`state.json`, `spend.json`, `nudges.json`, `seed-<ref>.json`, `blocks.json`, `poll.json`, `restart.json`). Change a key or its meaning → raise `FORMAT` in the same commit; a new key a reader can ignore isn't a change. A reader that meets another format acts on nothing and says to restart (`u`): `/fleet` lists such decisions apart and refuses to answer them, an asker doesn't deliver an answer it can't read, and an event or reads file of another format is counted in `/fleet status` and not used. A decision of a kind a reader doesn't know (a `change` carries no questions, so an older `fleet` can't answer it) is listed apart and never answered.
- **Person data has its own version**: the register (`registerFormat`, `REGISTER_FORMAT`; its closed decisions, recorded dialogs and the person's taste, `T-<n>`, and his corrections of a judge, `D-<n>.overrule.json`; a decision its asker took back (decide kind `withdraw`, or a new one filed with `supersedes`, only while he answered none of it) closes as `withdrawn`, with no judge entry and never in the case law; a record of a newer register format is left out of the judges' case law, never misread), `config.json` (`configFormat`, `CONFIG_FORMAT`), `world.json` (`worldFormat`, `WORLD_FORMAT` in `hooks/changes.ts`; a newer one turns the world off in that session, it never holds a write it can't read), `roster.json` (`rosterFormat`, `ROSTER_FORMAT` in `hooks/roster.ts`; `/fleet up` refuses a newer one), `outbound.json` (`outboundFormat`, `OUTBOUND_FORMAT` in `hooks/outbound.ts`; a newer or broken one allows nothing but this machine: the hard line never opens by itself) and `slots.json` (`slotsFormat`, `SLOTS_FORMAT` in `hooks/slots.ts`; a newer one has no pools). A poller's inbox item carries `itemFormat` (`ITEM_FORMAT` in `hooks/intake.ts`): a newer one waits in the inbox, counted in `/fleet status`. They only gain fields, a write keeps the fields it doesn't know, and a newer version is left untouched and said (restart, `u`), never silently ignored. A template's `template.json` has `templateFormat`; `/fleet init` refuses a newer one. An instance's settings file (`<project>/.claude/fleet/instances/<slug>.json`) is generated by every `/fleet up`, and written anew when the person accepts or applies a roster change (`/fleet accept roster.json`, `/fleet <n> apply`; never for an instance the lint finds an error for), so it carries no version (Claude would read a key of `fleet`'s as a setting).
- **The project folder is fleet's data folder.** `fleet` keeps no `$.store` and writes only in the project: its `<project>/.claude/fleet/`; on `/fleet init` the template's role files in `<project>/.claude/agents/` and its folders, never over a file that's there; and the command-level record an applied change names; the reproduction items the sweeper opens (`board/B-<n>.md`, from `world.json`'s `reproduce`); and on `/fleet init`, typed by the person, it takes out of `<project>/.claude/settings.local.json` a `sessions@…` key his user settings enable too (Plan B's enable adds it, and it would pin a copy of `sessions` to the project), backing the file up first, and has Claude uninstall a copy of `sessions` already pinned to the project (its own install record, through `claude plugin uninstall`); in a git repository, the roster it writes gets `"worktree": { "bgIsolation": "none" }` in its top-level settings when it doesn't say, so the instances' shared files are the main checkout's. It reads outside it only what Claude gives it (`CLAUDE_JOB_DIR`'s `state.json`, its own `plugin.json` and `templates/`, the person's user settings, `claude plugin list --json`, the command `FLEET_CLAUDE` names in a test) and the folder `FLEET_TEMPLATES_DIR` names; a new place it reads or writes outside the project gets an environment override, so test sessions never touch the owner's files.
- **Single writer or no-clobber.** A queue file is written once, by the session that asked, and so are a change's draft and diff, an outbound's call and a choice's proposal (`<project>/.claude/fleet/decisions/judge/`, published with `ln`); answers, drops, a change's claim when it's applied (an outbound's when it's sent), register records, prune markers, events (each under a name of its own; a Bash command's together, in one `sh` loop of `ln` through `run`), outside-change claims, a record's versions (on a name taken by the same text, folded onto it; else the next number), a version's correction (by the tool landing whose write a blind post-scan took first), a confirmation, an instance's seed marker, an intake record (the next I-<n> on a name taken), intake's dedup marks, an alert's claim (by the sweeper about to send it; given back when the send failed) a slot's lease (by its taker, or by whoever moved the first waiter's file out of line; one that ran out is taken back by moving it aside first, and put back if it isn't that one) and a run's three files (its declaration by its owner, the next run-<n> on a name taken; that its done-file appeared, by the sweeper; its result recorded, by its owner) are published with `ln` from a file in `<project>/.claude/fleet/decisions/tmp/` (the first one wins); notes, `last`, a session's own reads file and its judge ledger, an instance's heartbeat, spend, nudges, last poll (`poll.json`) and auto mode's blocks (only its own `fleet` writes them), its pending restart (`restart.json`: only the person's `/fleet up --restart-when-idle`, his `/fleet accept roster.json` or his apply of a change to it writes it, its time and `named` for one asked by name with its settings unchanged; the instance's own `fleet` reads it as pending while that time is after its process started, so a restart carries it out, and asks again after a refusal), the sweeper's `suspects.json` (its unproven files too), `commit.json`, `wakes.json`, `intake.json`, `alerts.json`, `code.json`, `work.json`, `pinned.json` and `reproduce.json`, a session's own marks of its writes in flight (`state/writing/<hash>-<session>-<thread>.json`: the text the write will leave and when it was first marked, rewritten every 10 s while the write waits, done after its event, honoured only while the file doesn't have that text yet; read only at this `format`, removed 10 minutes after their last rewrite), a lease its holder extends, a session's own place in a slot's line, a file's check results (whoever ran the check last wins), and the person's `stamps.json`, `lifts.json`, `down.json` and `channel-stamp.json` (the last write wins) replace with `mv`; `<project>/.claude/fleet/events/latest` is only a trigger, rewritten in place. The sweeper's lease (`<project>/.claude/fleet/state/sweeper.json`) is replaced with `mv` by whoever holds it or takes it once it's 90 s old (a session with Remote Control takes it from one without at once), and a taker sweeps only when it still finds itself there 2 s later: a minute of two sweepers is harmless, since what they write is idempotent. No locks.
- **Every command through `run`**, from `/` (it exists; every path is absolute), with a timeout; only a project's check script, a code watch's own two commands (stamped with the checks) (while it's as he stamped it, `/fleet accept channel`) and an outbound command the person approved run from a project folder (the project's, or the one the outbound was drafted in, when it still exists), and so does `/fleet init`'s `claude plugin uninstall sessions@… --scope local`, typed by the person (Claude's own command finds the project by its folder). `$.process.run` appears nowhere else.
- **Calls only to `sessions`** (`plugins/sessions/docs/plugin-contract.md`): never hook a `sessions.*` event, never read its state, store or `sessions-data/` files; find what's served with `has()` (raced against 500 ms; `start`, `wake` and `setMarks` came after api 1's first release, so they're called as `$.sessions.start!(…)` once `has()` said yes) and race every call; no `$.sessions` call in `session.start` (it runs before `sessions` starts). `dev/fleet/ci.sh` checks the first and the second.
- **Delivery state lives in `$.state`** (it survives a hot reload; module variables don't, and one double submit came from that): the decisions and overrules in flight, the person's notes that came after their answers left (told on their own once), a background Bash command's world as it started, the seed sent and a nudge in flight (what it carries is told only once its turn starts), a fresh period's hand-off until its turn starts, each thread's reads and the gate's "told once", the conversation's outside mark, whose turn is running (the person's, and the start of his words), when the conversation started and when it last landed, and the other sessions' decisions it said its work waits on (`decide` kind `wait`: told once each is settled; an instance's are in its heartbeat too, `waits`, and come back after a restart), what fleet's change dialog came to (told at the next step: it closes with no turn of its own), what an instance was told of the work around it (an item offered, a run finished, the front's capacity note: `workTold`) and what it had in flight after a restart or a compaction (`inFlightNote`, told once). What must outlive a restart is in the files (the outside mark in the reads file; an instance's last landing, conversation start, budget state and the text of its background commands, `bg`, in its heartbeat).
- **Light: two hard lines; a few things refuse once or refuse a helper (a stale write, a send allowed while a file its thread read changed since, a SendMessage in the same step as a refused write, the model's own PushNotification, a new helper over budget), and one refuses every time in an instance of the roster (a send the gate lets out that would wait at a prompt for the person, the organisation's ceiling ask or a rule's or hook's ask, which goes as a draft instead); everything else marks.** (1) The settings `/fleet up` writes for an instance deny its own tools (`Edit(//<path>)`, which covers Write) on the command-level files only (the charter, `principles.md`, `verify.md`, `roster.json`, `world.json`, `outbound.json`, `slots.json`, the role files, the check scripts and a code watch's commands' scripts and a command channel's script, `world.json`'s `"command"` records) and on `<project>/.claude/fleet/instances/` and the person's own state (`<project>/.claude/fleet/state/stamps.json`, `checks-stamp.json`, `channel-stamp.json`, `lifts.json`, `down.json`, `judges.json`); `fleet`'s gate refuses the same writes with how to file a `change`. A `change` is written by `fleet` only when the person applies it, once, while the file is at the version it was drafted on and the draft is the one filed or the one he confirmed; or as it's filed, when the person typed the turn that filed it (origin `composer`, never a launch prompt, matched to the turn by its text), never for `outbound.json`, and only once he says Apply in `fleet`'s own dialog in that session (`$.ui.ask` from a timer, never waited on inside the tool call; Esc or no dialog leaves it in his queue); in a conversation with an outside mark the dialog first says it was drafted after reading outside content, the diff a tap away. A `.py` draft that `python3 -I -W error` can't parse is refused before it's queued (one that can't be checked passes). (2) The one hard line, in background sessions only (and a session one started from its Bash, which inherited `CLAUDE_JOB_DIR` naming another session or `FLEET_INSTANCE`): a Bash command or MCP call that would send the project's content to a third party (`hooks/outbound.ts`) is refused with how to draft it (`mcp__fleet__send`); `fleet` runs a draft only when the person answers `send`, once (claimed no-clobber), exactly as shown, while the call and every file it sends are at the version he saw. The gate allows only what `outbound.json` says as stamped (`stamps.json` keeps its text; an edit made another way waits for `/fleet accept`; with no `stamps.json`, nothing but this machine, and nothing stamps a file the person didn't name: `/fleet init` writes the first stamps; a `calls` entry matches a URL key by the URL as a browser reads it, and a recipient-like key it can't read, a draft sent by its id or a reply to all holds the call; one with `source` and `body` passes only a text that is a contiguous span of that project file as it is now, less a declared `prefix`, markup and spacing set aside, and holds any other with where it departs), a remote name by the URL the project's own repository gives it. A send the gate lets through (a `calls` entry, his recipients) is refused once when a shared file its thread read in this turn or the last 12 hours changed since it read it (`warned`'s `send:<path>`, at the version it was refused at); the same call again passes. A gate that throws before the call ran refuses one that may reach the network (git's push, fetch, pull, clone, ls-remote and send-email, ssh, scp or rsync to a host, the other sending commands, an MCP tool); local git and a local copy run. No sandbox, no git denies, no other permission rule; a roster's own `permissions` are its, and `bypassPermissions` is never started. Besides, only code notifies the person: in a background session of the project the model's own PushNotification (`next.origin.plugin === 'engine'`) is refused and a plugin's own passes, and so is the model's own AskUserQuestion in an instance of the roster (it asks with `decide`; a plugin's `$.ui.ask`, such as `sessions`' Stop, passes, so roles keep the tool, and SendMessage, which `sessions` answers back through); `fleet` sends from the sweeper's timer through `roster.json`'s `person.channel` only (an MCP send to `person.channel.to`, one of his addresses, and no other recipient), never a file's content or a question's words, within `perDay` (a budget's and an instance with no fleet's in two more of their own), quiet hours and once per key a day, each claimed before it goes.
- **Intake is one stateless call per item, and never commands.** The sweeper reads each inbox item with one `$.model.complete` (no tools, the item as data between markers it can't close); code checks the answer (the vocabulary's tags, records as targets) and copies the sender and its `senderAuth` from the item, never from the model; the record is written by code, cites nothing, and its landing carries the kind, tags, sender, summary and routing, never the body. A request for a change becomes a pointer to one drafter, whose change the person confirms with its diff; from anyone but his addresses or a principal's it's a proposal; it alerts him, and wakes a retired instance, only when its platform verified the sender (an unverified claim of his address reaches its drafter labelled, and the brief). Within `perSourceHour` and `usdDay`; the MCP adapter calls only the listing tool `world.json` names.
- **A judge is one stateless call per choice, and answers only in a live area.** The asking session's `fleet` makes it from a timer once the ticket is out (`hooks/judges.ts`): the gates in code first and with no model (only a choice; never one its asker flags `touchesMoney` or `outsideWorld`, or `reversible: false`; `world.json`'s `skip` askers), then the soft gates, which let it propose in shadow but never answer, labelled `shadowOnly` (asked after reading outside content; `world.json`'s `judges.hold` patterns: domain words live there, never in code, and every template ships a money pattern), then an exact repeat by code, then one `$.model.complete` with no tools (none when nothing is on record: no answer of his in its area or sharing a word that carries meaning with it, and no line other than a heading in the charter, his principles or the rules: code holds it) (the statute cached first, the case law code picked, the question as data between markers it can't close). Code checks every citation (shown to the judge; a decision that answered the same question with that option, or a "no" naming it that isn't what it said no to; a statute line with a word that sets the option apart, or a short label itself, never `fleet`'s own lines of `principles.md`) and turns one that fails into a hold. Where nothing on record settles it, the judge may `suggest` an option instead of holding: shown beside the question, counted apart in `/fleet stats`, never acted on. The case law is the person's own answers, his corrections of a judge, the reasons he typed rejecting a change or an outbound, and the taste in his own words (his prompt, or his answer fleet delivered, in that turn: `said` verbatim, its about and principle labelled as the asker's reading; after outside content too, noted, and never what a live answer rests on), never a judge's own. In shadow (every area, by default) it never changes delivery: the proposal is shown, and the register keeps whether he agreed. Only in an area he turned live (`/fleet judges live`, typed by him, live at once: what it turns on is the exact repeats of his own answers), and only for a choice whose asker said `reversible: true`, `touchesMoney: false` and `outsideWorld: false`, within `perDay`, does it act: an exact repeat, and once the model's own verdicts earned it apart (`promote` on the ones he compared; turning the area live doesn't reach them) a decided verdict whose citations checked as a live answer's must (only `charter.md` and `principles.md` lines, no text answer), is published as the asker's answer with `origin: judge` (no-clobber: one the person typed first stays his) and delivered labelled; a send-back (the model's; one saying the statute answers it only with such checked lines, else it's shown and never acted on) is a drop with `origin: judge`, and an asker asking again within a day what was sent back to it goes to him. The person's `/fleet overrule` (typed) is published once beside the decision in the register and told to the asker once (before its asker had the judge's answer, his replaces it instead: claimed with `mv`, delivered as his, never told as an overrule); an area goes back to shadow by itself once he overrules 2 of the last 10 live answers he reviewed (overruled, or seen listed and let stand an hour; one he never saw counts neither way). A judge never touches a permission prompt, an outbound, money or what can't be undone.
- **Outside content marks, never holds.** WebFetch, WebSearch, an outside service's read, an intake record's read (an intake pointer told doesn't: it's a line fleet's code wrote) and a command's web read (`gh`'s reads of issues and pull requests too) mark the conversation until `/clear`, except what `outbound.json`'s `inside` names as the person's own (tools, hosts); the mark only sends a change through his dialog (his own turn) or his queue, keeps the judges to proposing, and labels what the session files; `/fleet status` names it, with the exact `inside` line for a connector of his own. It never travels through files: a reader of a marked session's file isn't marked (an event's `outside` is provenance for the brief).
- **A managed plugin can send the classic hooks on past `fleet`** (`next.to` beneath the user tier): what `fleet` does in them has a stand-in by events that don't go through them (who an instance is: fleet's own prompts, the next prompt after `/clear`, the conversation a compaction leaves; a permission prompt: `tool.check`'s verdict and ceiling; settled: any `tool.call`), and `/fleet status` says which classic hooks reached it.
- **The shared files are coordination, not security.** The gate refuses a stale write, or a write citing a pin its thread hasn't read as it is, once (no second try under `strict`), an Edit only for the pins it writes, never for a pin of exactly the version its thread read in the last 15 minutes (outside `strict`), and fails open (`.catch` → `next(e)`); Bash is never held, only recorded after the fact (landed blind: what a command names at once, what it changed and doesn't name only when no event explains it, as probably its, never the person's; a background command's once it completes, and what changes meanwhile as probably its); pins are read outside the change line, the highest version of each id only, and a landing whose body is the last version's (pins' numbers and change line aside) is editorial; suspects, failed checks and unproven records (a record `world.json`'s `proofs` says must carry a proof, `run:` and `sha:` or `source:` and `quote:`, with none that looks valid) are flags that hold nothing (an instance's journal is history, and so are the registers `world.json`'s `history` names: their pins are kept, they're never suspect nor refused for one, nor unproven); a digest carries path, who, when, versions and a check's message, never a file's content (of a change line only its kind). A check script runs only while the person's stamp (`/fleet accept checks`) matches the checks and their scripts, since `fleet` runs it as the person with no prompt; the proofs check re-runs only the `run:` commands `world.json`'s `proofs.rerun` lists (none by default: an instance writes the `run:` lines). The world commit adds and commits only world paths, with `--only`, never in a linked worktree, and never pushes.
- **The code watch tells and marks, never holds.** The sweeper polls each repository of `world.json`'s `code` (`hooks/code.ts`) with read-only commands only (git's `rev-parse`, `worktree list`, `log --name-only`, `diff --name-only`, `status --porcelain`, and `fetch` only when the repository says `"fetch": true`; p4's `changes`, `describe -s`, `opened`), through `ssh` only to a host `outbound.json` allows as stamped (never a prompt: `BatchMode`); a command repository's two commands run only while the checks' stamp covers them. An instance hears what moved upstream under files it changed or has open once (paths, who, the revision, when; never a commit's message), as a digest line or a nudge within its wakes, its row is marked (↻) until it has rebased or synced, and its own upstream change is never news to it. A poll that fails keeps the overlaps it knew and says why in `/fleet status`. Before a later wave, `/fleet up --wave n` shows each earlier instance's record (landings, checks, proofs, rejections and overrules, spend) and warns of one with nothing valid landed, never refusing.
- **Budgets and cadence mark, never hold.** At 80% only its row, the band and `/fleet status` say it (the instance isn't told: told to land what it had, instances wrapped up early); at 100% its row is marked, it's told, it's neither woken nor nudged, and a new helper (`agent.spawn`) is refused with why; its turn and every other tool go on. Once its budget is raised it hears once to resume, and a retired one whose last heartbeat was over is woken for it, once (`wakes.json`'s `budgetFor`). After a restart or a crash (sessions' `stopped: 'ended'`, or `'memory'` once memory is back) the sweeper wakes the instance by itself, once per stop (its last heartbeat), at most 3 a day, apart from the wakes' caps, never one the person stopped, one sessions can't say why stopped, one down or one over budget (`wakes.json`'s `restartFor`, `restartAt`, `restartCount`). An instance that lands nothing in its cadence period is marked (◷) and nudged (or woken) once each period while nothing lands, at most roster.json's `cadence.perDay` a day (3 by default, `null` for no cap; no cap while it owns open board items, and then only a landing other than its journal counts). Wakes are coalesced: an instance's own nudges (a digest, its intake pointers, a stale derived document it owns once its inputs are quiet `debounceMin` or 8 × `debounceMin` after they first moved, its own digest about them with it, a cadence, a fresh period) and the sweeper's wakes share `wakes.everyMin` and `wakes.perDay` (a slot given to it from the line, like an answer, waits ten minutes at most and isn't held by `perDay`); the sweeper wakes only an instance the service retired for being idle (or closed for memory), never one a restart stopped (the person's `/fleet up --stopped`) or one he stopped, and its cadence wakes and the instance's own cadence nudges are one count. `wakes.perDay: null` is no daily cap (only `everyMin` paces them); the forecast and the dry run count the wakes a day can hold, `min(perDay, 1440 / everyMin)`, each running instance at its own context. Changes another session lands under an instance's `watch` globs reach it in its nudges, and wake it when retired (`wakes.json`'s `watchFor`), within the same caps. A routine `poll` (`{ everyMin, prompt }`) is submitted by the instance's own `fleet` while it's idle, on its own count (`poll.json`), apart from the wakes' caps; twice overdue, its row is marked (⏲). The idle compaction (`compact`, on by default: idle `idleMin` 45 with at least `minTokens` 200000 in context) runs `/compact` from the instance's own timer once per idle spell; `false` turns it off. A pending restart waits until the instance is idle a minute with no background command, then asks `$.sessions.restart` (when `contract()` lists it; otherwise its heartbeat's `restartWait` says why, for `/fleet status`). `pin: true` asks `$.sessions.pin` once per job (when listed), so the service doesn't retire it. A change whose only cited authority is a derived document resting on its target is flagged (`circular`) and never applied as filed. A fresh period (every `freshH`, `cadenceH` by default; `/clear` from the instance's own timer, then its journal as `fleet`'s prompt) runs only when it's idle, nothing of `fleet`'s is on its way, and its journal was written since the conversation started. Auto mode's blocks only watch (`classic.PermissionDenied`, never a `retry`): an instance's `fleet` keeps a cut of today's, the brief and `/fleet status` say what in roster.json would allow each, and 3 in a day mark its row (⊘).
- **Work waiting is offered, never assigned; a run is watched, never held.** The sweeper offers an open board item nobody owns to one idle or retired instance its `for:` names (the front door without one; with no front door either, any instance but the item's writer, its first landing's), the one with the fewest offers and items, each instance it's for once (a round), the next one after 30 min; once all were offered it, no more until the item's file changes, then a new round within the wakes' caps (`work.json`'s offers, `mtime`, `round`, `allOffered`); a running instance hears a first round's offer from its own `fleet` as an urgent nudge (like an answer: within ten minutes, past `perDay`, not a cadence nudge), a retired one is woken for it. It writes one kind of item itself, never another: a result (`kind: result`) that `world.json`'s `reproduce` names (`{ glob, for }`), landed by an instance of another role, becomes `board/B-<n>.md` for that role, owner open, once per file (`state/reproduce.json`), only when no board item names it, published no-clobber (the next B-<n> on a name taken) and landed as fleet's own (`via: fleet`, `by: null`); every other item an instance takes or says why not. The capacity line, the band's "idle with queued work" flag and its "for nobody" (an item no instance can be offered: a `for:` that names nobody and no front door, or no `for:` and no instance but its writer) are marks. A declared run's done-file is read every 2 min, here or with `cat` over `ssh` only to a host `outbound.json` allows as stamped (`BatchMode`, never a prompt); its paths are plain characters only (`checkDeclare`), so nothing of the model's reaches a shell. A run that finished wakes its retired owner once (`wakes.json`'s `runsFor`); a run here whose log stayed still 2 h with no done-file is told to its owner once (`work.json`'s `quiet`). Runs are `run-<n>`, never a record's id. An instance's heartbeat carries its main thread's oldest tool call in flight (`call`); past 20 min (not a subagent's, not a permission prompt's), or the job's background MCP task (`state.json`'s `inFlight`, carried as `tasks`) seen that long, it's a mark, a line for the front door and an alert past `waitingMin`, nothing held. An instance's own `fleet` names the roster's model and effort on its main-loop requests (`turn.step`: a respawn replays the launch's `--model`, and `/model` in a background session waits on a dialog nobody answers); a request the account answers with nothing at all is sent again as the session named it, and that model isn't asked for again in the process (`modelRefused` in its heartbeat). A model or effort change alone needs no restart, nor does one of fleet's own deny rules (the settings hash an instance keeps leaves them out); an instance with a background MCP task or subagent counts as busy for capacity and offers; a fresh period waits while a restart is pending; a roster change the person accepts or applies rewrites the settings files and asks the restart when idle of a running instance whose other settings changed. A retired instance whose routine poll is due is woken for it on the poll's own count (`wakes.json`'s `pollFor`), and the pins `fleet` asked sessions for are kept in `<project>/.claude/fleet/state/pinned.json` (the sweeper's), so one the roster drops is unpinned.
- **No platform code.** `fleet` runs the same on macOS and Linux: `$.fs`, `$.clock`, `ln`, `mv`, `rm`, `mkdir`.
