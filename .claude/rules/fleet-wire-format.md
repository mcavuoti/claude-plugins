# fleet: its files carry a version, and it only calls `sessions`

`fleet` is turned on per project, and several sessions of a project run it at once, sharing the files under the project's `<project>/.claude/fleet/` (the list is at the top of `hooks/decisions.ts`). After an update the owner restarts every session, so there is no code for older versions: version skew must be harmless and visible, as in `sessions` (`.claude/rules/sessions-wire-format.md`).

- **Wire files carry `format`** (`FORMAT` in `hooks/decisions.ts`): `<project>/.claude/fleet/decisions/queue/`, `<project>/.claude/fleet/decisions/answers/`, `<project>/.claude/fleet/decisions/applied/`, `<project>/.claude/fleet/decisions/last`, `<project>/.claude/fleet/decisions/prune/`, `<project>/.claude/fleet/decisions/judge/` (a choice's proposal, `hooks/judges.ts`), `<project>/.claude/fleet/decisions/overrules/` (an overrule on its way to its asker and the reviewer), `<project>/.claude/fleet/events/` (the landings, `latest`, `claims/`), `<project>/.claude/fleet/reads/`, `<project>/.claude/fleet/state/` (a record's versions in `revs/`, `suspects.json`, `checks/`, `checks-stamp.json`, `sweeper.json`, `commit.json`, `stamps.json`, `lifts.json`, `down.json`, `wakes.json`, `intake.json`, `alerts.json`, `channel-stamp.json`, a slot's leases and line in `slots/`, a session's judge calls in `judges/<day>/`, the live areas in `judges.json`; `hooks/records.ts`, `hooks/roster.ts`, `hooks/intake.ts`, `hooks/channel.ts`, `hooks/slots.ts`), intake's dedup marks (`<project>/.claude/fleet/intake/seen/`) and an instance's `<project>/.claude/fleet/instances/<slug>/` (`state.json`, `spend.json`, `nudges.json`, `seed-<ref>.json`). Change a key or its meaning → raise `FORMAT` in the same commit; a new key a reader can ignore isn't a change. A reader that meets another format acts on nothing and says to restart (`u`): `/fleet` lists such decisions apart and refuses to answer them, an asker doesn't deliver an answer it can't read, and an event or reads file of another format is counted in `/fleet status` and not used. A decision of a kind a reader doesn't know (a `change` carries no questions, so an older `fleet` can't answer it) is listed apart and never answered.
- **Person data has its own version**: the register (`registerFormat`, `REGISTER_FORMAT`; its closed decisions, recorded dialogs and the person's taste, `T-<n>`, and his corrections of a judge, `D-<n>.overrule.json`; a record of a newer register format is left out of the judges' case law, never misread), `config.json` (`configFormat`, `CONFIG_FORMAT`), `world.json` (`worldFormat`, `WORLD_FORMAT` in `hooks/changes.ts`; a newer one turns the world off in that session, it never holds a write it can't read), `roster.json` (`rosterFormat`, `ROSTER_FORMAT` in `hooks/roster.ts`; `/fleet up` refuses a newer one), `outbound.json` (`outboundFormat`, `OUTBOUND_FORMAT` in `hooks/outbound.ts`; a newer or broken one allows nothing but this machine: the hard line never opens by itself) and `slots.json` (`slotsFormat`, `SLOTS_FORMAT` in `hooks/slots.ts`; a newer one has no pools). A poller's inbox item carries `itemFormat` (`ITEM_FORMAT` in `hooks/intake.ts`): a newer one waits in the inbox, counted in `/fleet status`. They only gain fields, a write keeps the fields it doesn't know, and a newer version is left untouched and said (restart, `u`), never silently ignored. A template's `template.json` has `templateFormat`; `/fleet init` refuses a newer one. An instance's settings file (`<project>/.claude/fleet/instances/<slug>.json`) is generated by every `/fleet up`, so it carries no version (Claude would read a key of `fleet`'s as a setting).
- **The project folder is fleet's data folder.** `fleet` keeps no `$.store` and writes only in the project: its `<project>/.claude/fleet/`; on `/fleet init` the template's role files in `<project>/.claude/agents/` and its folders, never over a file that's there; and the command-level record an applied change names; and on `/fleet init`, typed by the person, it takes out of `<project>/.claude/settings.local.json` a `sessions@…` key his user settings enable too (Plan B's enable adds it, and it would pin a copy of `sessions` to the project), backing the file up first. It reads outside it only what Claude gives it (`CLAUDE_JOB_DIR`'s `state.json`, its own `plugin.json` and `templates/`, the person's user settings, `claude plugin list --json`, the command `FLEET_CLAUDE` names in a test) and the folder `FLEET_TEMPLATES_DIR` names; a new place it reads or writes outside the project gets an environment override, so test sessions never touch the owner's files.
- **Single writer or no-clobber.** A queue file is written once, by the session that asked, and so are a change's draft and diff, an outbound's call and a choice's proposal (`<project>/.claude/fleet/decisions/judge/`, published with `ln`); answers, drops, a change's claim when it's applied (an outbound's when it's sent), register records, prune markers, events (each under a name of its own), outside-change claims, a record's versions (on a name taken, the next number) an instance's seed marker, an intake record (the next I-<n> on a name taken), intake's dedup marks and a slot's lease (by its taker, or by whoever moved the first waiter's file out of line) are published with `ln` from a file in `<project>/.claude/fleet/decisions/tmp/` (the first one wins); notes, `last`, a session's own reads file and its judge ledger, an instance's heartbeat, spend and nudges (only its own `fleet` writes them), the sweeper's `suspects.json`, `commit.json`, `wakes.json`, `intake.json` and `alerts.json`, a lease its holder extends, a session's own place in a slot's line, a file's check results (whoever ran the check last wins), and the person's `stamps.json`, `lifts.json`, `down.json` and `channel-stamp.json` (the last write wins) replace with `mv`; `<project>/.claude/fleet/events/latest` is only a trigger, rewritten in place. The sweeper's lease (`<project>/.claude/fleet/state/sweeper.json`) is replaced with `mv` by whoever holds it or takes it once it's 90 s old (a session with Remote Control takes it from one without at once), and a taker sweeps only when it still finds itself there 2 s later: a minute of two sweepers is harmless, since what they write is idempotent. No locks.
- **Every command through `run`**, from `/` (it exists; every path is absolute), with a timeout; only a project's check script, the person's command channel (while it's as he stamped it, `/fleet accept channel`) and an outbound command the person approved run from a project folder (the project's, or the one the outbound was drafted in, when it still exists). `$.process.run` appears nowhere else.
- **Calls only to `sessions`** (`plugins/sessions/docs/plugin-contract.md`): never hook a `sessions.*` event, never read its state, store or `sessions-data/` files; find what's served with `has()` (raced against 500 ms; `start`, `wake` and `setMarks` came after api 1's first release, so they're called as `$.sessions.start!(…)` once `has()` said yes) and race every call; no `$.sessions` call in `session.start` (it runs before `sessions` starts). `dev/fleet/ci.sh` checks the first and the second.
- **Delivery state lives in `$.state`** (it survives a hot reload; module variables don't, and one double submit came from that): the decisions and overrules in flight, the seed sent and a nudge in flight (what it carries is told only once its turn starts), a fresh period's hand-off until its turn starts, each thread's reads and the gate's "told once", the conversation's outside mark, whose turn is running (the person's, and the start of his words), when the conversation started and when it last landed. What must outlive a restart is in the files (the outside mark in the reads file; an instance's last landing and conversation start in its heartbeat).
- **Light: two hard lines; a few things refuse once or refuse a helper (a stale write, the model's own PushNotification, a new helper over budget); everything else marks.** (1) The settings `/fleet up` writes for an instance deny its own tools (`Edit(//<path>)`, which covers Write) on the command-level files only (the charter, `principles.md`, `roster.json`, `world.json`, `outbound.json`, `slots.json`, the role files, the check scripts and a command channel's script, `world.json`'s `"command"` records) and on `<project>/.claude/fleet/instances/`; `fleet`'s gate refuses the same writes with how to file a `change`. A `change` is written by `fleet` only when the person applies it, once, while the file is at the version it was drafted on and the draft is the one filed or the one he confirmed; or as it's filed, when the person typed the turn that filed it (origin `composer`, never a launch prompt, matched to the turn by its text) in a conversation with no outside mark, never for `outbound.json`. (2) The one hard line, in background sessions only (and a session one started from its Bash, which inherited `CLAUDE_JOB_DIR` naming another session or `FLEET_INSTANCE`): a Bash command or MCP call that would send the project's content to a third party (`hooks/outbound.ts`) is refused with how to draft it (`mcp__fleet__send`); `fleet` runs a draft only when the person answers `send`, once (claimed no-clobber), exactly as shown, while the call and every file it sends are at the version he saw. The gate allows only what `outbound.json` says as stamped (`stamps.json` keeps its text; an edit made another way waits for `/fleet accept`), a remote name by the URL the project's own repository gives it. A gate that throws before the call ran refuses one that may reach the network (git's push, fetch, pull, clone, ls-remote and send-email, ssh, scp or rsync to a host, the other sending commands, an MCP tool); local git and a local copy run. No sandbox, no git denies, no other permission rule; a roster's own `permissions` are its, and `bypassPermissions` is never started. Besides, only code notifies the person: in a background session of the project the model's own PushNotification (`next.origin.plugin === 'engine'`) is refused and a plugin's own passes; `fleet` sends from the sweeper's timer through `roster.json`'s `person.channel` only (an MCP send to `person.channel.to`, one of his addresses, and no other recipient), never a file's content or a question's words, within `perDay`, quiet hours and once per key a day.
- **Intake is one stateless call per item, and never commands.** The sweeper reads each inbox item with one `$.model.complete` (no tools, the item as data between markers it can't close); code checks the answer (the vocabulary's tags, records as targets) and copies the sender and its `senderAuth` from the item, never from the model; the record is written by code, cites nothing, and its landing carries the kind, tags, sender, summary and routing, never the body. A request for a change becomes a pointer to one drafter, whose change the person confirms with its diff; from anyone but his addresses or a principal's it's a proposal. Within `perSourceHour` and `usdDay`; the MCP adapter calls only the listing tool `world.json` names.
- **A judge is one stateless call per choice, and answers only in a live area.** The asking session's `fleet` makes it from a timer once the ticket is out (`hooks/judges.ts`): the gates in code first and with no model (only a choice; never one its asker flags `touchesMoney` or `outsideWorld`, or `reversible: false`; never one asked after reading outside content; `world.json`'s `judges.hold` patterns and `skip` askers: domain words live there, never in code), then an exact repeat by code, then one `$.model.complete` with no tools (the statute cached first, the case law code picked, the question as data between markers it can't close). Code checks every citation (shown to the judge; a decision that answered the same question with that option, or a "no" naming it that isn't what it said no to; a statute line with a word that sets the option apart, or a short label itself, never `fleet`'s own lines of `principles.md`) and turns one that fails into a hold. The case law is the person's own answers, his corrections of a judge, the reasons he typed rejecting a change or an outbound, and the taste in his own words (his prompt, or his answer fleet delivered, in that turn) in a clean conversation, never a judge's own. In shadow (every area, by default) it never changes delivery: the proposal is shown, and the register keeps whether he agreed. Only in an area he turned live (`/fleet judges live`, typed by him: the stats' threshold, or `--force`, recorded), and only for a choice whose asker said `reversible: true`, `touchesMoney: false` and `outsideWorld: false`, within `perDay`, does it act: an exact repeat, and once the model's own verdicts earned it apart (`promote` on the ones he compared; `--force` doesn't reach them) a decided verdict whose citations checked as a live answer's must (only `charter.md` and `principles.md` lines, no text answer), is published as the asker's answer with `origin: judge` (no-clobber: one the person typed first stays his) and delivered labelled; a send-back (the model's) is a drop with `origin: judge`. The person's `/fleet overrule` (typed) is published once beside the decision in the register and told to the asker once; an area goes back to shadow by itself once he overrules 2 of the last 10 live answers he reviewed (overruled, or seen listed and let stand an hour; one he never saw counts neither way). A judge never touches a permission prompt, an outbound, money or what can't be undone.
- **Outside content marks, never holds.** WebFetch, WebSearch, an outside service's read, an intake record's read, an intake pointer told and a command's web read (`gh`'s reads of issues and pull requests too) mark the conversation until `/clear`; the mark only keeps a change from being applied as filed and labels what the session files. It never travels through files: a reader of a marked session's file isn't marked (an event's `outside` is provenance for the brief).
- **The shared files are coordination, not security.** The gate refuses a stale write, or a write citing a pin its thread hasn't read as it is, once (no second try under `strict`), and fails open (`.catch` → `next(e)`); Bash is never held, only recorded after the fact (landed blind); suspects and failed checks are flags that hold nothing (an instance's journal is history: its pins are kept, it's never a suspect nor refused for one); a digest carries path, who, when, versions and a check's message, never a file's content (of a change line only its kind). A check script runs only while the person's stamp (`/fleet accept checks`) matches the checks and their scripts, since `fleet` runs it as the person with no prompt. The world commit adds and commits only world paths, with `--only`, never in a linked worktree, and never pushes.
- **Budgets and cadence mark, never hold.** At 80% an instance is told; at 100% its row is marked, it's neither woken nor nudged, and a new helper (`agent.spawn`) is refused with why; its turn and every other tool go on. An instance that lands nothing in its cadence period is marked (◷) and nudged once (or woken once). Wakes are coalesced: an instance's own nudges (a digest, its intake pointers, a stale derived document it owns once its inputs are quiet `debounceMin`, a cadence, a fresh period) and the sweeper's wakes share `wakes.everyMin` and `wakes.perDay` (a slot given to it from the line, like an answer, waits ten minutes at most). A change whose only cited authority is a derived document resting on its target is flagged (`circular`) and never applied as filed. A fresh period (`/clear` from the instance's own timer, then its journal as `fleet`'s prompt) runs only when it's idle, nothing of `fleet`'s is on its way, and its journal was written since the conversation started.
- **No platform code.** `fleet` runs the same on macOS and Linux: `$.fs`, `$.clock`, `ln`, `mv`, `rm`, `mkdir`.
